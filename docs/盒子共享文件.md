# 盒子共享文件

文件只放在各台盒子的 `/mmc/hmg`。系统库只记目录：哪台盒子有哪条路径、大小和 SHA-256。哪台盒子要用，就向同一管理员名下已经有这份文件的盒子要，写到自己磁盘上的同一条相对路径。

表一次建齐。先做扫描入库，再做盒子之间拿文件。

## 1. 路径

三个目录在每台盒子上名字相同。

| 桶 | 盒子磁盘 | 云机里 | 用途 |
| --- | --- | --- | --- |
| `share` | `/mmc/hmg/share` | `/dev/hmg/share` | 普通文件 |
| `video` | `/mmc/hmg/video` | `/dev/hmg/video` | 视频。复制进云机仍走现有的 `cp` |
| `mbp` | `/mmc/hmg/mbp` | `/dev/hmg/mbp` | 备份 |

`/mmc/hmg/fb` 是文件浏览器自己的数据，不进目录。`:18791` 仍只给人看本盒文件，不参与扫描和传递。

一条文件在目录里记成桶加相对路径。盒子上的 `/mmc/hmg/video/美女/1.mp4`、文件浏览器里的 `/sources/video/美女/1.mp4`、云机里的 `/dev/hmg/video/美女/1.mp4`，都是：

| 字段 | 值 |
| --- | --- |
| `bucket` | `video` |
| `parent_path` | `美女` |
| `name` | `1.mp4` |
| `relative_path` | `美女/1.mp4` |

根目录的 `parent_path` 是空字符串。相对路径用 `/` 分段。每一段不能是 `.` 或 `..`，不能含 `\`、空字符、制表符或换行，最长 180。整条 `relative_path` 最长 512。这和现在视频步骤对单段目录名、文件名的限制一致，只是允许多段目录。

另一台盒子的 IP、`/mmc`、`/sources`、`/dev/hmg` 都不写进路径。

## 2. 谁可以共享

共享范围是同一个管理员，取盒子上的 `device.assignee_user_id`。这个人是 init-tool 创建的管理员：`app_user.role = administrator` 且 `provisioned_by = init-tool`。

两台盒子要同时满足：

- `assignee_user_id` 相同，且不是空
- `enabled = true`
- `assignment_pending = false`
- `external_id` 不是空
- `group_id` 不是未分配组 `00000000-0000-4000-8000-000000000001`

管理员不同，目录接口不返回对方的行，也不签发拿文件的票据。未分配的盒子不参与共享。

页面上谁能看见这些盒子，沿用现在的 `GET /api/devices`：这位管理员本人，以及和他在同一个 `user_group` 里的成员。成员看见的仍是这一位管理员名下的盒子。

盒子改分给另一位管理员之后，目录行还在，但查询按当前的 `assignee_user_id` 过滤，原管理员立刻看不到，新管理员看得到。进行中的票据若两边管理员已经不一致，兑换失败。

## 3. 盒上的 agent

正式形态是盒子上的一个 linux/arm64 容器，`host` 网络，`DEVICE_HOST=127.0.0.1`。`host` 网络不会带上宿主磁盘，创建容器时要挂上这三份目录，读写都可以，因为拿到文件后要写进自己的树：

```text
/mmc/hmg/share:/mmc/hmg/share
/mmc/hmg/video:/mmc/hmg/video
/mmc/hmg/mbp:/mmc/hmg/mbp
```

不挂 `/mmc/hmg/fb`，不挂 Docker 套接字。扫描和写文件都走这个挂载，用 Go 遍历和计算 SHA-256。

| 变量 | 盒上的值 |
| --- | --- |
| `BACKEND_URL` | sys 的局域网地址，例如 `http://192.168.76.1:18080` |
| `BOX_ID` | `device.external_id` |
| `AGENT_TOKEN` | 这台盒子在 `device_agent` 里的令牌 |
| `DEVICE_HOST` | `127.0.0.1` |
| `HMG_SHARE_ROOT` | `/mmc/hmg` |
| `HMG_FILE_ADDR` | `:18793` |

`18793` 是给同一管理员的其他盒子来取文件的。`18790` 仍是本机日志页，只绑在回环地址。`18791` 仍是文件浏览器。

agent 对 sys 仍是出站 HTTP，`Authorization: Bearer`，`boxId` 为 `external_id`。sys 用令牌的 SHA-256 核对 `device_agent.token_hash`，和现在的 `/agent/*` 一样。

## 4. 数据表

迁移文件：`apps/api/src/db/migrations/0040_box_share.sql`。Drizzle 定义放在 `apps/api/src/db/schema/`。文件字节不入库。`storage_setting` 仍是原来的存储配置，不拿来记这些文件。

```sql
CREATE TABLE box_share_scan (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  device_id uuid NOT NULL REFERENCES device(id) ON DELETE CASCADE,
  status text NOT NULL DEFAULT 'pending',
  requested_by uuid REFERENCES app_user(id) ON DELETE SET NULL,
  started_at timestamptz,
  finished_at timestamptz,
  file_count integer NOT NULL DEFAULT 0,
  dir_count integer NOT NULL DEFAULT 0,
  skipped_count integer NOT NULL DEFAULT 0,
  error text NOT NULL DEFAULT '',
  created_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT box_share_scan_status_check
    CHECK (status IN ('pending', 'running', 'complete', 'failed'))
);

CREATE UNIQUE INDEX box_share_scan_one_active
  ON box_share_scan (device_id)
  WHERE status IN ('pending', 'running');

CREATE TABLE box_share_entry (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  device_id uuid NOT NULL REFERENCES device(id) ON DELETE CASCADE,
  bucket text NOT NULL,
  relative_path text NOT NULL,
  parent_path text NOT NULL,
  name text NOT NULL,
  kind text NOT NULL,
  size_bytes bigint NOT NULL DEFAULT 0,
  mtime timestamptz,
  sha256 text NOT NULL DEFAULT '',
  last_scan_id uuid NOT NULL REFERENCES box_share_scan(id) ON DELETE CASCADE,
  seen_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT box_share_entry_bucket_check CHECK (bucket IN ('share', 'video', 'mbp')),
  CONSTRAINT box_share_entry_kind_check CHECK (kind IN ('dir', 'file')),
  CONSTRAINT box_share_entry_sha_check CHECK (
    sha256 = '' OR sha256 ~ '^[0-9a-f]{64}$'
  ),
  CONSTRAINT box_share_entry_path_shape CHECK (
    name <> ''
    AND position('/' IN name) = 0
    AND char_length(relative_path) <= 512
    AND (
      (parent_path = '' AND relative_path = name)
      OR relative_path = parent_path || '/' || name
    )
  ),
  CONSTRAINT box_share_entry_path_unique UNIQUE (device_id, bucket, relative_path)
);

CREATE INDEX box_share_entry_list
  ON box_share_entry (device_id, bucket, parent_path);
CREATE INDEX box_share_entry_scan
  ON box_share_entry (device_id, last_scan_id);
CREATE INDEX box_share_entry_lookup
  ON box_share_entry (bucket, relative_path);

CREATE TABLE box_share_pull (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  assignee_user_id uuid NOT NULL REFERENCES app_user(id) ON DELETE CASCADE,
  source_device_id uuid NOT NULL REFERENCES device(id) ON DELETE CASCADE,
  target_device_id uuid NOT NULL REFERENCES device(id) ON DELETE CASCADE,
  bucket text NOT NULL,
  relative_path text NOT NULL,
  sha256 text NOT NULL,
  size_bytes bigint NOT NULL,
  status text NOT NULL DEFAULT 'pending',
  error text NOT NULL DEFAULT '',
  created_at timestamptz NOT NULL DEFAULT now(),
  started_at timestamptz,
  finished_at timestamptz,
  CONSTRAINT box_share_pull_bucket_check CHECK (bucket IN ('share', 'video', 'mbp')),
  CONSTRAINT box_share_pull_status_check
    CHECK (status IN ('pending', 'copying', 'complete', 'failed')),
  CONSTRAINT box_share_pull_sha_check CHECK (sha256 ~ '^[0-9a-f]{64}$'),
  CONSTRAINT box_share_pull_distinct_check
    CHECK (source_device_id <> target_device_id)
);

CREATE UNIQUE INDEX box_share_pull_one_active
  ON box_share_pull (target_device_id, bucket, relative_path)
  WHERE status IN ('pending', 'copying');

CREATE TABLE box_share_ticket (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  pull_id uuid NOT NULL REFERENCES box_share_pull(id) ON DELETE CASCADE,
  source_device_id uuid NOT NULL REFERENCES device(id) ON DELETE CASCADE,
  target_device_id uuid NOT NULL REFERENCES device(id) ON DELETE CASCADE,
  assignee_user_id uuid NOT NULL REFERENCES app_user(id) ON DELETE CASCADE,
  token_hash text NOT NULL UNIQUE,
  expires_at timestamptz NOT NULL,
  used_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX box_share_ticket_pull ON box_share_ticket (pull_id);
```

`box_share_entry` 不保存管理员。读的时候连接 `device.assignee_user_id`，改分配立即生效。

`parent_path` 是最终目录。文件 `美女/一月/1.mp4` 的 `parent_path` 是 `美女/一月`，`name` 是 `1.mp4`。目录行的 `kind` 为 `dir`，`size_bytes` 为 0，`sha256` 为空。文件行的 `sha256` 是 64 位小写十六进制，在盒子上算。

一次扫描完成之前保留旧目录。完成后删除这台盒子上 `last_scan_id` 不是本次的行。失败时标成 `failed`，旧目录不动。连续 10 分钟没有新的一批条目才算超时；扫描还在上报就保持 `running`。同一台盒子同时只有一条 `pending` 或 `running`。

`box_share_pull` 是一次拿文件。同一目标盒子、同一条路径同时只有一条 `pending` 或 `copying`。`box_share_ticket` 只存票据的 SHA-256，明文只在签发时返回给目标盒子的 agent。票据 10 分钟有效，兑换一次后写下 `used_at`。

## 5. 扫描

agent 只通过现有的 `POST /agent/tasks/claim` 领任务。心跳继续只上报在线、坑位和文件浏览器地址，回应里不增加扫描字段。

页面要扫某台盒子时，`POST /api/devices/{deviceId}/share-scans` 写一条 `box_share_scan`（`pending`），并写入一条 `execution_task`：`executor_key` 为 `box-agent`，只有一步，技能名 `ScanShare`。这一步不绑坑位，`instance_id` 为空，参数里带 `scanId`。已有进行中的扫描则不再建任务，返回原来的那一条。

agent 的长轮询领到 `ScanShare` 之后才读磁盘。这一步放在坑位队列之外执行，不占用 1 到 5 号云机的 worker。现有租约在 `instance_id` 为空时会锁住整台盒子；扫描不能用这条锁，否则上千个视频算哈希时，云机任务会一直领不走。扫描只占自己的 `execution_task_run`。心跳照旧把未过期的 run 续上 45 秒。

大小和修改时间与库里已有记录一致的文件，沿用原来的 SHA-256，不再读文件内容。只有新文件和改过的文件才在盒子上重算。

agent 从 `HMG_SHARE_ROOT` 遍历 `share`、`video`、`mbp`。普通文件和目录都要。不跟随符号链接。名字含制表符或换行的跳过，计入 `skippedCount`。文件的 SHA-256 在本机计算，不把文件发回 sys。

分批上报，每批最多 200 条。现有 POST 正文上限是 3MB。

```http
POST /agent/share-scans/{scanId}/entries
Authorization: Bearer <这台盒子的 agent 令牌>
Content-Type: application/json
```

```json
{
  "boxId": "8ff1697abf4db615d9f02ba8744f5e38",
  "entries": [
    {
      "bucket": "video",
      "path": "美女/1.mp4",
      "kind": "file",
      "size": 1048576,
      "mtime": "2026-10-09T12:00:00Z",
      "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
    },
    {
      "bucket": "video",
      "path": "美女",
      "kind": "dir",
      "size": 0,
      "sha256": ""
    }
  ]
}
```

sys 确认令牌对应的 `device_id` 就是 `scan.device_id`，且扫描是 `pending` 或 `running`。第一批把状态改成 `running` 并写 `started_at`。按 `(device_id, bucket, relative_path)` 做 upsert，更新大小、时间、哈希、`last_scan_id` 和 `seen_at`。`path` 在服务端拆成 `parent_path` 和 `name`。路径不合法则整批 400。扫描不属于这台盒子则 401。

```http
POST /agent/share-scans/{scanId}/complete
```

```json
{
  "boxId": "8ff1697abf4db615d9f02ba8744f5e38",
  "fileCount": 12,
  "dirCount": 3,
  "skippedCount": 0,
  "error": ""
}
```

`error` 为空时，在一个事务里检查本次文件行都有 64 位哈希，删除该盒子 `last_scan_id` 不是本次的行，再把扫描标成 `complete`，并把这条 `ScanShare` 任务回报为 `succeeded`。`error` 非空，或有文件没有哈希，扫描标成 `failed`，任务回报为 `failed`，不删旧行。agent 中途退出后，任务按现有恢复回到队列；agent 再次领取同一条 `ScanShare`，整棵树重扫再完成。

给人看的接口使用登录态，盒子必须通过第 2 节的可见范围：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/api/devices/{deviceId}/share-scans` | 新建 `pending`。已有进行中的扫描则返回那一条，200；新建 202 |
| `GET` | `/api/devices/{deviceId}/share-scans/latest` | 最近一次扫描的状态、数量、错误、时间 |
| `GET` | `/api/devices/{deviceId}/share-entries?bucket=video&parent=美女&limit=100` | 这个最终目录的直接子项，按页返回。`parent` 为空是桶的根 |

子项按目录在前、名称排序。响应里带本次扫描状态，以及每条的 `id`、`name`、`kind`、`path`、`size`、`mtime`、`sha256`。

同一管理员名下谁持有这条文件：

```http
GET /api/share-entries/holders?bucket=video&path=美女/1.mp4
```

只返回 `assignee_user_id` 与当前可见管理员相同、且在线的盒子。字段是盒子 `id`、`host`、`name`，以及该行的 `size`、`mtime`、`sha256`。

## 6. 拿文件

拿文件也是 agent 领取的任务，技能名 `PullShare`，不绑坑位，租约规则和 `ScanShare` 相同。页面或复制视频发现本机没有这条路径时，先写入 `box_share_pull` 和一条 `execution_task`。目标盒子的 agent 从 `POST /agent/tasks/claim` 领到之后，才向 sys 要票据。sys 核对两边管理员相同、源盒子在线、源目录里有这条文件且带哈希。已有相同哈希的本地文件则直接完成，不再传字节。本地哈希不同则拒绝，不覆盖。源盒子不领取发送任务，只在 `:18793` 上应答。

```http
POST /agent/share-pulls
Authorization: Bearer <目标盒子的 agent 令牌>
```

```json
{
  "boxId": "目标盒子的 external_id",
  "sourceDeviceId": "源盒子的 device.id",
  "bucket": "video",
  "path": "美女/1.mp4"
}
```

成功时写入 `box_share_pull`（`pending`）和 `box_share_ticket`，把明文票据只返回给目标 agent：

```json
{
  "pullId": "...",
  "sha256": "...",
  "size": 1048576,
  "expiresAt": "2026-10-09T13:10:00Z",
  "url": "http://192.168.76.140:18793/files/video/美女/1.mp4",
  "ticket": "只出现这一次的明文"
}
```

`url` 的主机用源盒子的 `device.host`。目标 agent 接着取字节：

```http
GET http://192.168.76.140:18793/files/video/美女/1.mp4
Authorization: Bearer <ticket>
```

源盒子的 agent 不凭这张票据直接读盘。它先向 sys 兑换：

```http
POST /agent/share-tickets/redeem
Authorization: Bearer <源盒子自己的 agent 令牌>
```

```json
{ "boxId": "源盒子的 external_id", "ticket": "明文" }
```

sys 核对票据哈希、未过期、未使用、`source_device_id` 就是这台盒子，并且两边当前的 `assignee_user_id` 仍等于签发时的管理员。通过后写 `used_at`，把拉取改成 `copying`，返回 `bucket`、`path`、`sha256`。源 agent 只打开 `HMG_SHARE_ROOT` 下面的这个相对路径，确认没有越出该桶，再把原始字节写回 `18793` 的响应。响应头带 `X-Content-Sha256`。

目标 agent 在本机先建父目录，写到 `相对路径.partial`，边写边算 SHA-256。与票据里的哈希一致才换名为正式文件，然后：

```http
POST /agent/share-pulls/{pullId}/complete
```

```json
{ "boxId": "目标盒子的 external_id", "sha256": "...", "error": "" }
```

成功则拉取标成 `complete`，并 upsert 目标盒子的 `box_share_entry`。失败标成 `failed`，删掉 `.partial`，原有正式文件保留。票据已兑换就不能再用，失败后重新申请。

源盒子关机或心跳已离线，这次申请直接失败。10 分钟没有 complete，sys 把拉取标成 `failed`。

云机使用不经过 `18793`。文件到了本机 `/mmc/hmg/video` 之后，仍是原来的命令：

```sh
cp "/dev/hmg/video/美女/1.mp4" "/sdcard/Movies/1.mp4"
```

## 7. 落地顺序

1. 建第 4 节的四张表。agent 挂上三个目录。页面建 `ScanShare` 任务，agent 领取后扫描。页面能看到一台盒子的最终目录和文件哈希。
2. 打开 `18793`。页面建 `PullShare` 任务，目标盒子领取后把一条视频写到相同相对路径。哈希相同则跳过，哈希不同则不覆盖。
3. 复制视频之前，若本机没有这条 `relative_path`，先排队 `PullShare`，agent 领取完成后再执行原来的 `cp`。
