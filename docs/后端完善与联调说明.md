# 积分商场与商家中心：后端完善与联调说明

本文只覆盖 2026-11-07 这一轮的积分商场和商家中心改动。

## 做了什么

| 模块 | 能力 |
|---|---|
| 钱包 | 积分归属分组，1 元 = 100 积分；流水只增不改 |
| 充值 | 平台方人工充值和调账；分组成员用支付宝充值 |
| 商品 | 上下架、改价、库存增减、绑定库存分组 |
| 购买 | 分组成员用积分购买；改价保护；并发下不超卖 |
| 发货 | 平台方从来源分组把账号或代理转给买家 |
| 售后 | 未发货可取消；已发货可退款，默认收回资源 |
| 转移 | 平台方在分组之间手动转移账号和代理，有记录 |
| 发票 | 成员申请，平台方开具或驳回；企业必填税号；PDF 可下载 |
| 导出 | 我的订单按当前筛选导出 CSV |

## 业务规则

- **权限：** 商家中心的页面和接口只对平台方开放（`role=administrator` 且不是 `restrictGroups`），其他人访问接口得到 404，并写入拒绝审计。只有分组成员能替分组花积分、充值和申请发票，平台方也不例外。
- **转移保留什么：** 账号密码和代理凭据、来源分组的历史记录。
- **转移清掉什么：** 设备、代理、备份信息、转移码、标签、备注。
- **不能转移：** 正在跑任务（含取消中、等重试）、有未开始的派发、被租用占用的账号和代理；还绑着账号或在加速链路里的代理。
- **退款：** 退的是积分，不退现金，商品库存不自动增加。收回失败时整笔不动；操作人可以选择不收回。
- **可开票额度：** 实际收到的钱（人工和支付宝充值），减去待审和已开的发票。驳回后额度退回。调账赠送的积分不算。
- **库存：** 商品绑定库存分组后，只能从该分组发货；买家看到的库存不超过“分组里能发的数量减去待发货占用”；库存分组自己的成员不能买这个商品。没绑定的商品仍按手工库存销售，发货时可选任意分组。
- **收回范围：** 退款只收回这笔订单发出去的。发货后又被转走的（包括后来被另一笔订单发回来的）不会自动收回，要选“不收回”或手动处理。

## 配置

支付宝是可选的。下面前四项都填好才启用，否则页面不显示“充值”按钮，下单接口返回 503。缺回调地址或密钥解析不了时，启动日志会写明原因（不含密钥内容）。

| 变量 | 说明 |
|---|---|
| `ALIPAY_APP_ID` | 应用 ID |
| `ALIPAY_PRIVATE_KEY` | 应用私钥，PEM，或 PKCS8、PKCS1 的裸 base64 |
| `ALIPAY_PUBLIC_KEY` | 支付宝公钥（不是应用公钥） |
| `ALIPAY_NOTIFY_URL` | 回调地址，`https://<域名>/api/pay/alipay/mall/notify`，必须公网可达 |
| `ALIPAY_RETURN_URL` | 付款后跳回的页面，可不填 |
| `ALIPAY_GATEWAY` | 默认正式网关；沙箱联调时改成沙箱地址 |

密钥只放在部署环境，不要提交，也不要写进日志。

支付宝回调丢失时有两道补救：

- 买家在充值弹窗里点“我已付款”时主动查询。
- API 进程每 5 分钟补查超过 35 分钟未付的订单，付了就入账。支付宝确认关闭的立刻关单；查不到交易的等 2 小时才关，因为买家可能还停在收银台；一直查不出结果的等 1 天才关。

关单后仍会继续查 48 小时，这期间付的款照样入账，再晚只能靠回调或人工核对。

通过 nginx 部署时，发票上传接口已单独放宽到 6MB，其他接口仍是默认的 1MB。如果前面还有别的反向代理，也要放宽。

## 数据库迁移

四个迁移都是增量的，按顺序自动执行：

| 迁移 | 内容 |
|---|---|
| `0077`、`0078` | 钱包、流水、订单、商品 |
| `0079` | 转移记录；账号绑代理、新建派发项时校验归属的触发器 |
| `0080` | 发票和发票文件、退款和支付字段、商品绑定库存分组 |

`0079` 的触发器只在值变化时检查，历史上遗留的跨分组绑定不会让普通编辑报错。

`0079` 和 `0080` 给 `mall_order` 加了状态和时间一致性的检查约束。如果数据库里已经有手工写入的 `shipped` 订单没有 `shipped_at`，或 `paid` 订单没有 `paid_at`，迁移会失败，上线前先查一下。

## 回滚

- **关支付宝：** 清空 `ALIPAY_*` 并重启 API。已付款的订单不受影响，未付款的订单之后不会再被补查，需要时手工核对。
- **回滚代码：** 迁移只增不减，旧代码可以继续跑在新表结构上，但会读不到新状态（`refunded`、`closed`、`unpaid`）的语义。有这些状态的订单后再回滚，要先确认旧页面的展示可以接受。
- **撤销一次转移：** 在“账号转移”或“代理转移”页面转回去。设备绑定、标签等已清掉的内容不会恢复。
- **撤销一次退款：** 没有反向操作，用“调账”扣回积分。

## 还没解决的

- **卖家仍可能知道密码：** 来源分组的历史派发里存着当时的明文密码，买家明细里提示了“建议尽快修改密码”。
- **部分代理查不出占用：** 任务链后续阶段临时抽取的代理没有记录。库存代理不要放进正在跑任务的分组。
- **买家可能无法永久删除账号：** 账号在来源分组跑过任务时，永久删除返回 409，要等来源分组清掉派发记录。
- **旧的转移码功能：** 兑换后还保留原来的设备、代理和备份信息，这是原有行为，这轮没改。
- **没有现金退款：** 支付宝充值的钱不会原路退回，退款只退积分。需要退现金时走线下。
- **没绑定库存分组的商品：** 发货时操作人可以选任意分组，选错只能手动转回。建议给所有在售商品绑定库存分组。
- **极少数并发：** 账号绑定或新建派发撞上转移时，可能返回一次 500，重试即可，数据不会出错。
