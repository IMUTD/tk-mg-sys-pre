# 积分商场与商家中心：后端完善与联调说明

本文覆盖 2026-11-07 这一轮的积分商场和商家中心改动，以及 2026-11-15 的账号分级。

## 做了什么

| 模块 | 能力 |
|---|---|
| 钱包 | 积分归属分组，1 元 = 100 积分；流水只增不改 |
| 充值 | 平台方人工充值和调账；分组成员用支付宝充值 |
| 商品 | 上下架、改价、库存增减、绑定库存分组 |
| 购买 | 分组成员用积分购买；改价保护；并发下不超卖 |
| 发货 | 平台方从来源分组把账号或代理转给买家 |
| 售后 | 未发货可取消；已发货可退款，默认收回资源 |
| 转移 | 平台方在分组之间手动转移账号和代理，有记录 |
| 发票 | 成员申请，平台方开具或驳回；企业必填税号；PDF 可下载 |
| 导出 | 我的订单按当前筛选导出 CSV |

## 业务规则

- **权限：** 商家中心的页面和接口只对平台方开放，其他人访问接口得到 404，并写入拒绝审计。只有分组成员能替分组花积分、充值和申请发票，平台方也不例外。
- **账号分级（2026-11-15，2026-11-18 加客户方）：**

  | 级别 | 怎么来 | 初始化工具 | 积分商场 | 商家中心、客户管理 | 成员与权限 |
  |---|---|---|---|---|---|
  | 平台方 | 部署时创建，`app_user.is_platform = true` | 能登录，看全部 | 可以 | 可以 | 看到所有用户 |
  | 客户方（一级） | 平台方在“客户管理”创建，`app_user.is_customer = true` | 能登录，只看自己名下 | 可以 | 不可以 | 看到名下盒子管理员分组里的成员；建二级时要选放进哪个分组 |
  | 盒子管理员（一级） | 客户方或平台方在初始化工具里创建 | 不能登录 | 可以 | 不可以 | 看到自己分组的成员，可以建二级 |
  | 二级用户 | 在“成员与权限”里创建 | 不能登录 | 不可以 | 不可以 | 不能再建成员 |

  客户方和盒子管理员都是一级用户，接口返回的 `level` 都是 `primary`，客户方另有 `isCustomer` 标记。“成员与权限”页面已恢复成和 `main` 一样的平铺列表；客户方新建成员时多一个“所属分组”下拉框。平台方只认 `is_platform` 标记，没有标记的管理员按一级处理，只能看自己的分组。二级用户的积分商场页面不能勾选，已经存过的勾选会被忽略但不删除。
- **客户方：** 平台方在“客户管理”里填名称、邮箱和密码创建，同时建一个同名分组，客户方的积分记在这个分组上；也可以停用和重置密码，停用或改密码会让管理系统和初始化工具里的登录一起失效。客户方在初始化工具里建盒子管理员时，新管理员的 `parent_user_id` 指向客户方，客户方也加入新管理员的分组，所以在管理系统里能看到名下盒子管理员的盒子、账号和任务；积分商场里客户方能在自己和名下盒子管理员的分组之间切换。客户方建的二级用户挂在所选分组的盒子管理员名下。
- **初始化工具登录（`IMUTD/hmg-init-tool` 的 `feat/customer-login` 分支）：** 只有平台方和客户方能登录，用管理系统的邮箱和密码（argon2id，也认原来的 bcrypt）。除 `meta` 和登录接口外都要登录。客户方只看到未分配的盒子和分给自己名下盒子管理员的盒子，只能管理自己建的盒子管理员；盒子配额和盒子费用只有平台方能看。平台方建盒子管理员时可以选归属客户，也可以不选。
- **转移保留什么：** 账号密码和代理凭据、来源分组的历史记录。
- **转移清掉什么：** 设备、代理、备份信息、转移码、标签、备注。
- **不能转移：** 正在跑任务（含取消中、等重试）、有未开始的派发、被租用占用的账号和代理；还绑着账号或在加速链路里的代理。
- **退款：** 退的是积分，不退现金，商品库存不自动增加。收回失败时整笔不动；操作人可以选择不收回。
- **可开票额度：** 实际收到的钱（人工和支付宝充值），减去待审和已开的发票。驳回后额度退回。调账赠送的积分不算。
- **库存：** 商品绑定库存分组后，只能从该分组发货；买家看到的库存不超过“分组里能发的数量减去待发货占用”；库存分组自己的成员不能买这个商品。没绑定的商品仍按手工库存销售，发货时可选任意分组。
- **收回范围：** 退款只收回这笔订单发出去的。发货后又被转走的（包括后来被另一笔订单发回来的）不会自动收回，要选“不收回”或手动处理。

## 配置

支付宝是可选的。下面前四项都填好才启用，否则页面不显示“充值”按钮，下单接口返回 503。缺回调地址或密钥解析不了时，启动日志会写明原因（不含密钥内容）。

| 变量 | 说明 |
|---|---|
| `ALIPAY_APP_ID` | 应用 ID |
| `ALIPAY_PRIVATE_KEY` | 应用私钥，PEM，或 PKCS8、PKCS1 的裸 base64 |
| `ALIPAY_PUBLIC_KEY` | 支付宝公钥（不是应用公钥） |
| `ALIPAY_NOTIFY_URL` | 回调地址，`https://<域名>/api/pay/alipay/mall/notify`，必须公网可达 |
| `ALIPAY_RETURN_URL` | 付款后跳回的页面，可不填 |
| `ALIPAY_GATEWAY` | 默认正式网关；沙箱联调时改成沙箱地址 |
| `BOX_SERVICE_ALIPAY_NOTIFY_URL` | 盒子时长的回调地址，`https://<域名>/api/pay/alipay/notify`。可不填，不填时用 `ALIPAY_NOTIFY_URL` 的域名拼这个路径 |
| `BOX_SERVICE_ALIPAY_RETURN_URL` | 盒子时长付款后跳回的页面，可不填，不填就回到下单所在域名的盒子时长页 |

盒子时长和商城共用同一个支付宝应用（上面三项密钥和网关），但回调、回跳地址各用各的，不能都填进 `ALIPAY_NOTIFY_URL`。

密钥只放在部署环境，不要提交，也不要写进日志。

支付宝回调丢失时有两道补救：

- 买家在充值弹窗里点“我已付款”时主动查询。
- API 进程每 5 分钟补查超过 35 分钟未付的订单，付了就入账。支付宝确认关闭的立刻关单；查不到交易的等 2 小时才关，因为买家可能还停在收银台；一直查不出结果的等 1 天才关。

关单后仍会继续查 48 小时，这期间付的款照样入账，再晚只能靠回调或人工核对。

通过 nginx 部署时，发票上传接口已单独放宽到 6MB，其他接口仍是默认的 1MB。如果前面还有别的反向代理，也要放宽。

## 数据库迁移

这些迁移都是增量的，按顺序自动执行：

| 迁移 | 内容 |
|---|---|
| `0077`、`0078` | 钱包、流水、订单、商品 |
| `0079` | 转移记录；账号绑代理、新建派发项时校验归属的触发器 |
| `0080` | 发票和发票文件、退款和支付字段、商品绑定库存分组 |
| `0081` | `app_user.is_platform`；把现有非初始化工具建的管理员回填为平台方 |
| `0086` | `app_user.is_customer`；只允许非平台方、非初始化工具建的管理员被标成客户方，现有账号不回填 |

`0079` 的触发器只在值变化时检查，历史上遗留的跨分组绑定不会让普通编辑报错。

`0081` 的回填和迁移前的判断一致，所以上线时现有账号的权限不变。之后再用 `bootstrap-admin` 或 `bootstrap-deployment` 建的管理员会写上标记；直接往库里插的管理员默认不是平台方。数据库约束不允许初始化工具建的账号或非管理员被标成平台方。

`0079` 和 `0080` 给 `mall_order` 加了状态和时间一致性的检查约束。如果数据库里已经有手工写入的 `shipped` 订单没有 `shipped_at`，或 `paid` 订单没有 `paid_at`，迁移会失败，上线前先查一下。

## 回滚

- **关支付宝：** 清空 `ALIPAY_*` 并重启 API。已付款的订单不受影响，未付款的订单之后不会再被补查，需要时手工核对。
- **回滚代码：** 迁移只增不减，旧代码可以继续跑在新表结构上，但会读不到新状态（`refunded`、`closed`、`unpaid`）的语义。有这些状态的订单后再回滚，要先确认旧页面的展示可以接受。
- **撤销一次转移：** 在“账号转移”或“代理转移”页面转回去。设备绑定、标签等已清掉的内容不会恢复。
- **撤销一次退款：** 没有反向操作，用“调账”扣回积分。
- **回滚账号分级：** 旧代码不读 `is_platform`，又会按“不是初始化工具建的管理员”判断平台方；二级用户原来勾选的积分商场权限会重新生效。
- **回滚客户方：** 旧代码不读 `is_customer`，客户方会被当成没有标记的管理员（只看自己所在的分组，仍然包括名下盒子管理员的分组）。初始化工具要一起退回 `feat/scan-lock-and-quota`，退回后它又不需要登录。

## 还没解决的

- **卖家仍可能知道密码：** 来源分组的历史派发里存着当时的明文密码，买家明细里提示了“建议尽快修改密码”。
- **部分代理查不出占用：** 任务链后续阶段临时抽取的代理没有记录。库存代理不要放进正在跑任务的分组。
- **买家可能无法永久删除账号：** 账号在来源分组跑过任务时，永久删除返回 409，要等来源分组清掉派发记录。
- **旧的转移码功能：** 兑换后还保留原来的设备、代理和备份信息，这是原有行为，这轮没改。
- **没有现金退款：** 支付宝充值的钱不会原路退回，退款只退积分。需要退现金时走线下。
- **没绑定库存分组的商品：** 发货时操作人可以选任意分组，选错只能手动转回。建议给所有在售商品绑定库存分组。
- **初始化工具要先升级管理系统数据库：** 初始化工具登录要读 `is_platform`、`is_customer`、`parent_user_id`，管理系统没跑到 `0086` 时登录会提示先升级数据库。部署时先跑管理系统迁移，再换初始化工具。
- **已有盒子管理员没有归属客户：** 之前在初始化工具里建的盒子管理员 `parent_user_id` 为空，客户方看不到，只有平台方能管。要归到某个客户名下得手工改库（设 `parent_user_id`，并把客户方加进他的分组），页面上还没有这个操作。
- **初始化工具配额测试偶发失败：** 初始化工具开配额时用程序时钟写开始时间，分配盒子时用数据库时钟判断，并发跑测试时偶尔会报“没有有效配额”。原分支同样会出现，这轮没改。
- **客户方能看到名下盒子管理员的明文密码：** 初始化工具原来就把盒子管理员的明文密码存在 `password_plain` 并显示在账号页，客户方登录后也能看到自己名下的，这是原有行为。
- **二级用户改其他二级：** 被勾选了“成员与权限”的二级用户仍能编辑、停用和删除同分组的其他二级用户，只是不能新建。
- **页面没在浏览器里点过：** “客户管理”页面和初始化工具登录页这轮只做了组件测试和接口联调，浏览器自动化工具没启动起来，需要人工点一遍。
- **极少数并发：** 账号绑定或新建派发撞上转移时，可能返回一次 500，重试即可，数据不会出错。
## 2026-10-30 盒子时长、支付宝支付与到期限制

整体架构、接口、配置和可见范围见 `docs/系统架构.md` 第 4 节。这里只记部署要点。

- 新增迁移 `0082_box_service`、`0083_app_user_parent`、`0084_box_service_refund`、`0085_box_service_device_missing`，都是增量迁移，可以直接跑（从 tk-mg-sys 合并过来时从 0058–0061 重新编号）。
- `0083` 加的 `parent_user_id` 只在新建成员时写入，已有成员留空，他们的管理员暂时看不到这些成员的订单。
- 到期限制默认只对 `192.168.76.166` 生效。要调整就设置 `BOX_SERVICE_LIMITED_HOSTS`；设成 `*` 限制全部盒子。
- `infra/compose.prod.yml` 已经传 `ALIPAY_*`、`BOX_SERVICE_PRICE_*`、`BOX_SERVICE_LIMITED_HOSTS`，在部署机的 `.env` 里填好支付宝三项就能开放下单。
- api 每 5 分钟向支付宝补查一次超时未付的订单，回调丢了也能到账；只跑一个 api 实例即可，多实例时补查会重复但不会重复加时长。
- 回退：把 api 镜像退回上一版即可，新加的列和状态不影响旧代码。只是退回后，状态为 `refunded` 的订单在旧页面上会没有对应的状态名。
