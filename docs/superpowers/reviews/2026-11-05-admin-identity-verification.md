## 交付行为

- init-tool 创建的 administrator 可上传身份证人像面，单独勾选同意，通过阿里云二要素 OCR 核验后绑定当前账号。没有活体、人脸比对或证件有效期核验。
- sys 创建的 administrator 为平台账号，可查看脱敏列表，按账号、状态、认证日期筛选，查看认证及解绑记录。
- 解绑要求平台操作人密码、原因、当前版本和独立请求键。本地事务清空当前身份、释放证件占用、作废在途核验、撤销目标全部会话并写审计；不调用阿里云解绑，也不删除历史订单或任务。
- 同一身份证同时只能绑定一个账号。姓名、证件号使用现有 AES-GCM 加密；独立 HMAC 密钥用于当前绑定查重。图片仅用于请求处理，不写应用持久存储。
- enforced 时未认证的目标管理员只能认证、查询会话或退出；门禁覆盖生产组装中晚注册的购买和任务下发接口。普通成员、平台账号、Agent、支付验签回调按原规则工作。
- 默认 off；optional 开放认证但不限制业务。云端错误不会自动放宽 enforced。

## 评审后修正

| 问题 | 落实方式 |
| --- | --- |
| 重放请求可能被当作新调用限流 | 幂等查询和当前状态检查先于解码及收费额度预占；最终事务再次检查 |
| Redis 重试可能拖住认证 | 额度、冷却和密码失败限制均由 PostgreSQL 原子处理 |
| 两张业务表无法持久共享密码失败窗口 | 新增小型 identity_password_failure 表，5 次失败 / 15 分钟 |
| 解绑、同步停用和核验回写有竞争 | 统一用户行→认证行锁顺序；版本、流水 ID、状态及截止时间再次核对；停用触发作废在途请求 |
| SDK Advance 不止一个请求 | 锁定官方 SDK 版本，测试授权上传、OSS 上传、核验三阶段；禁用自动重试；超时结果不能回写 |
| 大图片并发占内存 | 字节/像素/格式限制，实际解码，每进程最多 2 个并发解码，finally 释放名额 |
| 原页面请求未统一处理解绑后的 401/403 | 原生 fetch 与 ky 客户端接入同一响应观察器；清理会话和用户查询缓存 |
| 旧请求的 401 可能清除新登录 | 请求捕获会话代次，登录/退出/账号变化推进代次；异步处理后再次核对 |
| 丢失响应后的失败重试复用旧键 | 本地查询确认终态后清除请求键；回归先复现、再验证修复 |
| 代理修改 Host 导致同源校验失败 | nginx 保留原 Host/端口，Vite /api 不修改 Origin Host；真实代理验证 |
| 认证数据可能缓存、窄屏/深色主题可读性 | 所有认证路由 no-store；强制认证使用独立响应式布局和 Ant Design 主题背景 |

## 文件与模型

- 后端：`apps/api/src/modules/identity-verification/`，分离配置、云适配、解码、预占、完成事务、查询、解绑及路由。
- 增量迁移：`0061_admin_identity_verification.sql`，三张新表、约束/索引、解绑审计幂等索引、用户停用触发器；Drizzle 显式 schema 列表已更新。
- 业务状态：unverified / verifying / verified / rejected / error / unbound；流水状态：verifying / verified / rejected / error / superseded。历史 verified 不代表当前仍绑定。
- 门禁与会话：`modules/access/identity-gate.ts`、`modules/auth/identity-session.ts`；原权限与分组校验不扩权。
- 前端：`features/identity-verification/`；平台历史接口同时返回 attempts 和 unbindings。身份证展示如 `110***********002X`。
- 网关/运行：三个 nginx 配置、Compose、环境示例、启动配置及每分钟租约清理。
