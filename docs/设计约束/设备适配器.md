# 设备适配器设计约束

## 状态与目标

仓库当前没有真实云手机供应、投屏传输、设备控制协议或任务执行器。`packages/device-adapter` 已提供厂商无关契约、内存适配器和未配置适配器；`apps/api` 已能持久化设备命令并编排健康检查、claim、租约和取消，但生产默认使用未配置适配器。`apps/web` 的设备命令页面只展示 API 返回的状态，不代表真实设备已接入。

真实供应方接入时，新增 `packages/device-adapter` 内的独立实现，不改变 API 契约。API 业务层只依赖统一接口，不能直接调用厂商 SDK、HTTP API、WebSocket 或内网盒子协议。适配器用于隔离尚未确定的设备供应方，不能被当作任务编排或权限系统。

```text
Web -> API routes/services -> DeviceAdapter -> vendor cloud / box / emulator
                         -> PostgreSQL task and command records
```

## 最小契约

第一版以设备状态、实例清单和异步命令为中心。命令应使用仓库生成的 UUID，并携带设备/实例、幂等键、类型和已校验参数；适配器返回供应方回执，不返回供应方特有的数据模型。

```ts
interface DeviceAdapter {
  health(target: DeviceTarget): Promise<DeviceHealth>
  listInstances(deviceId: DeviceId): Promise<readonly DeviceInstanceSnapshot[]>
  submit(command: DeviceCommand): Promise<DeviceCommandReceipt>
  getResult(commandId: DeviceCommandId): Promise<DeviceCommandResult>
  cancel(commandId: DeviceCommandId): Promise<void>
}
```

命令先支持 `health_check`、`capture_screen`、`launch_app`、`stop_app`、`tap`、`swipe` 和 `input_text`。每种命令已有 Zod schema、明确超时、可序列化错误码与脱敏参数。截图等产物由 API 保存引用和访问策略，不把二进制或凭据直接返回页面；当前内存实现没有真实截图产物时返回 `no_artifact`。

## 责任边界

适配器负责协议翻译、连接超时、供应方回执与错误归一化。它不负责成员权限、账号分配、任务状态机、数据库事务、审计、重试策略或浏览器 UI。

API 在提交前验证用户、分组、设备归属和业务状态；再持久化命令与审计事件。外部调用不得放在数据库事务内。命令仓储使用 `(group_id, device_id, idempotency_key)` 做本地幂等约束，并用 claim token、租约、条件更新、取消标记和有限轮询防止旧执行结果覆盖新 claim。独立执行器仍未实现。

## 实现与测试顺序

当前已实现 `InMemoryDeviceAdapter`，模拟成功、超时、不可用、取消和异步完成，并通过共享契约测试；`autoComplete` 只有显式本地演示/测试配置才启用。`createUnconfiguredDeviceAdapter` 在生产未接入供应方时返回稳定的 `unconfigured` 错误。供应方协议确定后新增独立实现，例如 `VendorCloudPhoneAdapter` 或 `InternalBoxAdapter`；不得改变 API DTO 或前端任务流程。

真实投屏是独立的实时通道，不属于 CRUD 或命令轮询接口。只有在供应方能力、鉴权模型和网络拓扑确定后，才设计其 WebSocket/WebRTC 网关。

真实供应商接入前，请按《设备适配器厂商对接清单》确认身份、能力、幂等、取消、截图、安全和可靠性语义。
