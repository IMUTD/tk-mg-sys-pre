# TK-MG-SYS 代码架构

本文说明 `tk-mg-sys` 仓库的整体结构，以及每个源码文件的职责。目标是让你能按目录找到模块，再按文件理解它在系统里做什么。

测试文件（`*.test.ts` / `*.test.tsx` / `e2e/*.spec.ts`）统一在各节末尾说明，不逐文件展开。设计文档与运维手册见文末「相关文档」。

---

## 1. 系统是什么

这是一套部署在内网的运营后台，复刻原站中「注册资源」和「运营中心」的信息架构，不依赖原站 API。

| 角色 | 能做什么 |
|------|----------|
| 管理员 | 全部页面（含成员与权限、工作日志）；可为每个成员微调最终页面权限；运营概览不能删除 |
| 运营员 | 运营中心（不含配置中心）+ 资源中心；默认不能删除 |
| 运营部长 | 运营中心全页 + 运营业绩 + 资源中心；本部门与资源中心默认可删除 |
| 销售员 | 营销中心 + 积分商场 + 资源中心；默认不能删除 |
| 销售部长 | 销售页 + 资源中心；本部门与资源中心默认可删除 |
| 工程师 | 工程中心 + 资源中心；默认不能删除 |
| 工程部长 | 工程 / 资源页；本部门与资源中心默认可删除 |

规则：

- 登录仍用邮箱当账号。登录后顶栏和个人设置显示 `display_name`（成员名字），不显示邮箱。
- `canView` 才能看见菜单并进页；增改跟查看走一起。`canDelete === true` 才显示删除按钮并允许删除 API，不能用「能看就能删」兜底。
- `/members`、`/work-logs` 只有管理员能看，权限面板不能下放。
- `/overview` 谁都不能开删除（含管理员）。
- 资源中心对所有角色默认可看，删除只有部长级和管理员。

技术基线：TypeScript monorepo、React 管理前端、Hono + Bun API、PostgreSQL、Redis、Docker Compose。

## 2. 总体架构

```text
运营人员浏览器
    │ HTTPS / Cookie 会话
    ▼
管理前端 apps/web  ──►  API apps/api
                          │ 鉴权、RBAC、业务、审计
                          ▼
                    PostgreSQL          Redis
                    业务数据 / 审计      会话就绪探测 / 缓存
                          │
                          ▼
                 Worker apps/worker（任务 outbox / 恢复）
                          │
                          ▼
                  storage-adapter（NAS 接口）
                   device-adapter（厂商无关设备协议接口）
```

要点：

- 独立 Bun Worker 读取 PostgreSQL outbox、领取任务并恢复过期租约；没有真实厂商协议或投屏传输。
- Web 不直接访问数据库或 Redis，一律走 `/api`。
- API 是编排中枢：写库、鉴权；盒子 CRUD、账号租约、注册资源等走后端。运营中心任务列表页仍是前端本地数据，不调用新任务 API。
- NAS 协议被隔离在 `packages/storage-adapter`，业务代码不直接调厂商 SDK。
- `packages/device-adapter` 已提供厂商无关契约、内存适配器和未配置适配器；真实厂商协议仍未接入。接口与边界见 `docs/设计约束/设备适配器.md`。

### 两端协作路径

1. 浏览器登录 → API 写会话 Cookie `tk_mg_session`。
2. 页面请求 `/api/*`（开发走 Vite 代理，生产走 nginx 反代）。
3. 盒子管理、任务列表等云大师对齐页以本地 mock 为主；设备详情 / 新建走设备 CRUD API。

## 4. 如何阅读业务代码

API 各模块分层固定，看到文件名就能判断职责：

| 文件 | 职责 |
|------|------|
| `routes.ts` | HTTP 入参校验、鉴权、状态码 |
| `service.ts` | 业务规则、审计、密钥加解密编排 |
| `repository.ts` | 领域类型 + 仓储接口；常含内存实现供单测 |
| `postgres-repository.ts` | PostgreSQL 实现 |
| `route-authorization.ts` | 该模块的权限 / 分组校验 |

装配链：`main.ts` → `composition.ts`（接线 DB/Redis/各 service）→ `app.ts`（挂路由）。

没有全局 Hono 中间件链。鉴权在各 handler 内完成。Cookie 名：`tk_mg_session`。

前端按功能域放在 `apps/web/src/features/<域>/`：`api.ts` 调后端，`*-page.tsx` 是页面。

## 6. 共享包 `packages/`

### 6.1 `@tk-mg/storage-adapter`

NAS 存储边界。页面和业务服务不直接调用 SMB / NFS / S3 SDK。当前生产路径多为「未配置」占位。

| 文件 | 作用 |
|------|------|
| `package.json` / `tsconfig.json` | 包元数据与 TypeScript 配置。 |
| `src/index.ts` | 再导出接口、内存实现、超时包装与错误。 |
| `src/types.ts` | `StorageAdapter`：list / get / put / move / mkdir / remove / stat / capacity / health。 |
| `src/in-memory.ts` | 内存实现（测试用）+ `createUnconfiguredStorageAdapter`（health = unconfigured）。 |
| `src/errors.ts` | `StorageUnavailableError`、`StorageTimeoutError`。 |
| `src/timeout.ts` | `withStorageTimeout`：用 Promise.race 给存储调用加超时。 |

### 6.2 `@tk-mg/device-adapter`

设备供应方和协议尚未确定，因此当前只落地厂商无关边界：`DeviceAdapter` 定义健康检查、实例查询、异步命令提交、结果查询和取消；`InMemoryDeviceAdapter` 供契约测试与显式本地演示使用；`createUnconfiguredDeviceAdapter` 用于生产未配置状态。API 负责鉴权、命令状态、审计和 PostgreSQL 持久化；适配器只负责协议翻译、超时及错误归一化。真实供应方接入前不得把内存实现当成设备能力。

### 6.3 `@tk-mg/task-execution`

`commands.ts` 拒绝不可重放的 `input_text`；`lifecycle.ts` 定义合法状态迁移；`policy.ts` 提供有界重试、超时与租约策略；`redaction.ts` 将敏感字段递归变为类型/长度信息。`repositories.ts` 规定 API 任务事务契约，`worker-repository.ts` 是独立 Worker 使用的 PostgreSQL outbox、claim token、lease 与恢复实现。二者不相互导入 app 源码。

## 7. 后端 `apps/api`

包名 `@tk-mg/api`。运行时：Bun + Hono；持久化：postgres.js + Drizzle 迁移；校验：Zod；机密字段：AES-256-GCM。Redis 仅用于就绪探测 ping。

### 7.1 入口与装配

| 文件 | 作用 |
|------|------|
| `package.json` | 依赖 storage-adapter、task-execution、hono、postgres、drizzle、ioredis、zod。`test:postgres` 包含执行任务 schema、仓储及历史设备命令回归。 |
| `tsconfig.json` | 继承仓库基线，`include: ["src"]`，Bun types。 |
| `drizzle.config.ts` | Drizzle Kit：PostgreSQL，schema 包含独立 execution task 表，迁移输出到 `src/db/migrations`。 |
| `src/main.ts` | 校验 `DATABASE_URL` / `PORT` / `REDIS_URL` / `SECRET_ENCRYPTION_KEY`，`Bun.serve` 启动。`/ready` 走就绪检查，其余交给 Hono。SIGINT / SIGTERM 优雅关闭。 |
| `src/composition.ts` | 生产装配：创建 SQL、Redis、各 Postgres repository、密钥 cipher、全部 service，并注入可选 `DeviceAdapter`；未配置时使用 `createUnconfiguredDeviceAdapter`。提供 `checkReadiness`（`select 1` + Redis ping）与 `close`。 |
| `src/app.ts` | 创建 Hono：`GET /health`；在 auth + audit 就绪后按可选依赖注册全部业务路由。 |
| `src/bootstrap-admin.ts` | CLI：用 `ADMIN_BOOTSTRAP_*` 幂等插入首个管理员（已存在则失败）。Docker profile `bootstrap` 会跑它。 |

### 7.2 数据库客户端

| 文件 | 作用 |
|------|------|
| `src/db/client.ts` | `postgres(url, { max: 10 })` 连接池。 |
| `src/db/test-database.ts` | 集成测试专用：要求 `TEST_DATABASE_URL` 库名以 `tk_mg_test_` 开头，advisory lock 后重建 schema 并 migrate。 |

### 7.3 横切工具 `src/lib/`

| 文件 | 作用 |
|------|------|
| `authorization.ts` | 七种角色、权限枚举、`AccessScope`、分组范围；`canViewPage` / `canDeletePage`（工作日志与成员页仅管理员；概览锁死不删）。 |
| `pages.ts` | 页面目录、`ADMIN_ONLY` / `NO_DELETE` / 资源中心公开矩阵、角色默认可见与删除、映射回 `devices:*` 等 API 权限。 |
| `crypto.ts` | AES-256-GCM 加解密，密文格式 `v1.iv.tag.ciphertext`。账号密码、代理凭证、NAS 凭证、webhook 等走这里。 |
| `operation-claim-guard.ts` | 删除前检查活跃 task claim / 资源分配 / 账号租约，冲突则抛 `OperationDeleteConflictError`。 |

权限常量：

- `configuration:write`
- `devices:read` / `devices:write`
- `operations:read` / `operations:write`
- `resources:read` / `resources:write`

### 7.4 表结构 `src/db/schema/`

#### `auth.ts` — 身份、分组、会话、审计、系统设置

| 表 | 含义 |
|----|------|
| `access_group` | 运营分组（数据范围边界） |
| `app_user` | 用户：邮箱（登录账号）、展示名、密码哈希、角色、是否启用 |
| `user_group` | 用户 ↔ 分组多对多 |
| `role_page_permission` | 角色 × 页面：可查看 / 可删除（管理员不入库） |
| `user_page_permission` | 成员最终页面权限；新建时从角色默认矩阵复制 |
| `app_session` | 会话：token 哈希、过期、撤销 |
| `audit_event` | 不可变审计：操作者、动作、结果、目标、元数据 |
| `system_setting` | KV：系统名、任务重试策略 JSON、可选加密 webhook |

#### `devices.ts` — 盒子库存

| 表 | 含义 |
|----|------|
| `device` | 主机设备：host / model / 是否桥接 / 健康状态，归属某个 group |
| `device_instance` | 设备实例（index / label），含实例级健康与播放诊断 |

#### `registration-resources.ts` — 注册资源

| 表 | 含义 |
|----|------|
| `registration_resource` | 邮箱 / SMS / OAuth / POP3 等注册用凭证；指纹去重；secret 加密 |

#### `operations.ts` — 运营账号 / 资源 / 代理

| 表 | 含义 |
|----|------|
| `operation_resource` | 可分配运营资源（available / allocated / inactive） |
| `operation_account` | 运营账号（密文凭证，组内 identifier 唯一） |
| `operation_account_lease` | 账号租约（同时仅一个活跃） |
| `operation_resource_allocation` | 资源分配给账号（同时仅一个活跃） |
| `operation_proxy` | 代理端点 + 加密凭据 |

#### `tasks.ts` — 任务编排

| 表 | 含义 |
|----|------|
| `operation_task_template` | 模板：name、parameters、`executor_key` |
| `operation_task` | 任务实例：状态机、幂等键、取消 / 心跳字段 |
| `operation_task_run` | 运行日志行 |
| `operation_task_allocation` | 任务占用的 resource / account |
| `operation_task_claim` | 对 resource / account / proxy / device-instance 的排他占用 |

#### `storage.ts` — 私有云配置

| 表 | 含义 |
|----|------|
| `storage_setting` | 协议 / host / rootPath + 可选加密凭据 |

### 7.6 业务模块 `src/modules/`

模块间关系（简图）：

```text
auth（会话） ──► 几乎所有模块
audit（审计）──► 所有写操作与拒权路径
access（权限判定）──► devices / resources / registration-resources / …

account-pool ──读账号──► accounts
resources.allocate ──绑定──► accounts
resources/route-authorization.ts  被 accounts / account-pool / proxies 共用
```

#### `auth` — 登录会话

| 文件 | 作用 |
|------|------|
| `routes.ts` | `POST /api/auth/login`、`/logout`，`GET /api/auth/session`；写 / 清 HttpOnly cookie；会话返回邮箱、展示名、角色与页面矩阵 |
| `service.ts` | 登录登出会话逻辑；token SHA-256 存库；`Bun.password` 校验密码 |
| `postgres-repository.ts` | 用户（含 `display_name`）+ 分组查询；按成员最终页面矩阵生成 Permission；会话 CRUD |
| `user-repository.ts` | 插入 `app_user`（引导管理员等场景） |

#### `access` — 权限判定与地基探测

| 文件 | 作用 |
|------|------|
| `service.ts` | `requirePermission`（管理员全放行）、`requireGroupAccess`、`requirePageDelete` |
| `page-authorization.ts` | 按页面 `canView` / `canDelete` 拦截；无查看权返回 404，无删除权返回 403 |
| `administrator-authorization.ts` | 要求 administrator；非管理员记审计并返回 404（避免泄露管理接口存在） |
| `routes.ts` | `GET /api/groups/:groupId/resources`（占位空列表）、`GET /api/foundation/configuration` |

#### `audit` — 审计

| 文件 | 作用 |
|------|------|
| `service.ts` | `writeAuditEvent`；内存 / Postgres 仓储 + 管理员查询列表 |
| `routes.ts` | `GET /api/audit`：仅管理员（工作日志页）分页查询，可按 action / actor / group / 时间过滤 |

审计不记录解密后的凭证。

#### `members` — 成员与权限（仅管理员）

| 文件 | 作用 |
|------|------|
| `routes.ts` | `GET/POST /api/members`，`PATCH/DELETE /api/members/:memberId`，`GET/PUT /api/members/:memberId/permissions`，页面目录与分组 |
| `service.ts` | 创建 / 更新 / 删除成员；随机名字；密码哈希 + 可复制密文；新建时写入角色默认页面权限 |
| `repository.ts` | 接口 + Postgres / 内存：事务写 user + user_group |
| `page-permission-repository.ts` | `user_page_permission` 最终权限；空表时按角色默认矩阵补种；保存后吊销该成员会话 |
| `display-names.ts` | 动漫 / 影视 / 动物 / 明星名字池 |

#### `settings` — 系统配置（需能查看配置中心）

| 文件 | 作用 |
|------|------|
| `routes.ts` | `GET/PATCH /api/settings/system`（需能查看配置中心） |
| `service.ts` | 读写公开设置；加密 webhook；`taskPolicy` 作为通用配置字段保存。 |
| `repository.ts` | `system_setting` 中 key=`system` 的 get / save |

#### `storage` — 私有云存储配置

| 文件 | 作用 |
|------|------|
| `routes.ts` | `GET /api/storage/status` 与 `GET/PATCH /api/storage/configuration`（需能查看私有云储存页） |
| `service.ts` | 加密凭据；经 storage-adapter 做健康检查 |

#### `task-execution` — 独立执行任务 API

`POST/GET /api/groups/:groupId/tasks`、`GET /api/groups/:groupId/tasks/:taskId` 和 `POST /api/groups/:groupId/tasks/:taskId/cancel` 使用运营权限、任务页权限和组级可见性。`service.ts` 解析设备命令并生成稳定请求指纹与脱敏 DTO；`postgres-repository.ts` 在事务中写 task、step、event、outbox 与审计。任务级 `parameters` 只能省略或传 `{}`，`executorKey` 只接受已实现的执行器；`input_text` 不支持，直到有加密的可重放引用存储。按组和幂等键重复提交返回同一任务，变更内容返回 409；跨组访问隐藏为 404。只有管理员可通过组内 `POST .../tasks/:taskId/reconcile` 以不含原始供应商数据的证据引用人工处理 `needs_reconciliation`，重复相同决议不重复记账。此 API 不连接现有前端任务页。

前端联调的请求示例、响应字段、错误码和已知限制见《任务执行前端对接.md》。

## 8. 独立 Worker 与设备协议边界

`apps/worker/src/main.ts` 从 PostgreSQL outbox 领取工作，`runtime.ts` 控制轮询、有限并发、恢复与 SIGTERM 停止，`executor.ts` 通过共享契约调用适配器并持久化步骤。生产默认 `createUnconfiguredDeviceAdapter()`；内存适配器仅供测试，真实设备协议尚未接入。API `/ready` 与 worker 启动都要求 `TK_MG_SYSTEM_ACTOR_ID` 指向已有且禁用的管理员用户；Compose worker 健康检查只在健康标记为 `ready` 时通过，并等待 API 健康。outbox 为至少一次投递：完成后、确认投递前重启可重复投递事件，但不能重复提交已完成的供应商命令。提交标记后的超时或未知结果隔离设备并进入 `needs_reconciliation`，不得据此声称供应商物理执行恰好一次；具体启动顺序及环境界限见《本地启动》。

- 任务列表页使用本地 mock，可创建 / 终止展示，不会写库、不会入队、不会在盒子上执行。
- 设备命令 API 会写入 `device_command`、`device_command_event` 和审计记录；没有执行器领取时命令保持持久化状态，未配置适配器的健康检查明确返回 `unconfigured`。
- 盒子管理页同样以本地列表为主；远程控制通过 `window.open` 打开盒子自身页面，不经过本仓库的播放器 API。
- Redis 只做 API 就绪探测；任务 outbox 在 PostgreSQL，不使用 BullMQ。

| 登录、会话、成员与权限、审计、系统设置 | 后端持久化 | API 使用 PostgreSQL；核心路径有 Bun 单测，敏感设置不回显。 |
| 盒子、注册资源、运营资源、账号、代理、私有云配置 | 后端持久化 | 有 API 模块、表结构和路由测试；私有云协议调用仍通过 storage-adapter 边界。 |
| Web 管理后台导航、权限菜单、主要表格与弹窗 | 前端可用 | Vitest 覆盖主要交互；Playwright `auth.spec.ts` 覆盖最小浏览器认证/权限冒烟。 |
| 任务列表、任务记录、营销、积分商场、部分运营工作台数据 | 前端本地数据 | 用于对齐信息架构和交互，不代表后端执行能力。 |
| NAS 真实读写 | 边界已定义，生产配置待接入 | `packages/storage-adapter` 定义接口、内存实现、未配置占位和超时包装。 |
| 任务执行 Worker 与设备适配边界 | 已实现，真实协议待接入 | PostgreSQL outbox、租约恢复、终态投影和人工复核已实现；生产未配置适配器不会伪造真实设备执行。投屏/云手机协议仍未实现。 |
