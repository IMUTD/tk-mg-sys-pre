# 任务执行 API：前端对接

本页以当前 `apps/api/src/modules/task-execution/{routes,service}.ts` 和
`packages/device-adapter/src/commands.ts` 为准。执行任务 API 是独立领域，不是历史
`operation_task*` 表或现有运营中心任务页的本地数据接口。设备列表已走 API；任务页目前仍使用
本地数据。不要把页面中的数字设备 ID、脚本 ID 或模板参数直接发给执行任务 API。

## 访问与权限

- 浏览器只请求同源 `/api`，沿用登录所得的 HttpOnly `tk_mg_session` Cookie；请求需携带
  credentials。不要在前端保存或手动拼接会话 token。
- `groupId`、`deviceId`、`instanceId`、`taskId` 都使用真实 UUID。先从
  `GET /api/auth/session` 取得登录态和页面权限；`GET /api/access/groups` 要求设备页查看权，
  已有设备客户端使用它；`GET /api/groups/:groupId/devices` 返回该组已登记设备与实例。
  仅有任务页权限而没有设备页权限时，不要假设可访问设备列表；需另定设备选择契约。
- 所有任务接口要求该组可访问且 `Tasks` 页面 `canView=true`。读接口要求
  `operations:read`，提交和取消要求 `operations:write`。不按 `canDelete` 决定能否取消。
  只有 `BackgroundTasks` 或 `TaskRecords` 页面权限不能访问这些接口。
- 人工复核还要求管理员角色、显式 `operations:write`、`Tasks` 页面查看权，并且
  `groupId` 存在于管理员的 `scope.groupIds` 中。它不是普通操作员的任务操作。

## 提交任务

`POST /api/groups/:groupId/tasks`，`Content-Type: application/json`，必须提供非空
`Idempotency-Key` 请求头。建议在用户确认创建时生成一个键，并在同一创建请求的网络重试中
复用；用户重新发起不同任务时生成新键。不能在超时后无条件换键重发。

```http
POST /api/groups/11111111-1111-4111-8111-111111111111/tasks
Content-Type: application/json
Idempotency-Key: create-20260930-001

{
  "name": "设备健康检查",
  "executorKey": "device-command",
  "steps": [
    {
      "type": "health_check",
      "target": {
        "deviceId": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa"
      }
    }
  ]
}
```

字段规则：

| 字段 | 规则 |
| --- | --- |
| `name` | 必填，去空格后 1-200 字符；当前不会出现在任务列表/详情 DTO 中 |
| `executorKey` | 只接受 `device-command` |
| `parameters` | 省略或 `{}`；不能放脚本、凭据或其他参数 |
| `maxAttempts` | 可省略，默认 3；整数 1-10 |
| `steps` | 必填，有序数组，1-100 步；所有步骤必须指向同一设备及同一实例（或全部不指定实例） |
| `target` | `deviceId` 必须是该组已登记设备的 UUID；`instanceId` 可省略，存在时必须属于该设备 |

步骤类型及附加字段（除 `type`、`target` 外）：

| `type` | 附加字段 |
| --- | --- |
| `health_check`、`capture_screen` | 无 |
| `launch_app`、`stop_app` | 非空字符串 `appId` |
| `tap` | 有限非负数 `x`、`y` |
| `swipe` | 有限非负数 `fromX`、`fromY`、`toX`、`toY`；正整数 `durationMs` |

`input_text`、未知命令和额外目标字段会返回 400。不要发送供应商 JSON、明文输入、密码、
token，也不要传内部字段 `commandId`、`idempotencyKey` 或 `timeoutMs`（由服务端生成）。
创建成功返回 **202** 和下述 `SafeTask`；相同组内同一个键和等价内容再次提交返回
**200** 及同一任务；同键但内容不同返回 **409**。

## 查询、取消、复核

| 操作 | 接口 | 成功响应 |
| --- | --- | --- |
| 列表 | `GET /api/groups/:groupId/tasks?page=1&pageSize=20` | 200，`{items,total,page,pageSize}`；页码从 1 开始，大小 1-100，默认 20，按创建时间倒序 |
| 详情 | `GET /api/groups/:groupId/tasks/:taskId` | 200，`SafeTask` |
| 请求取消 | `POST /api/groups/:groupId/tasks/:taskId/cancel` | 200，当前 `SafeTask`；取消可能尚未完成，继续查询状态 |
| 管理员人工复核 | `POST /api/groups/:groupId/tasks/:taskId/reconcile` | 200，`{taskId,state}`；只对 `needs_reconciliation` 的任务进行决议 |

人工复核 JSON 形如
`{"resolution":"failed","evidenceRef":"CASE_20260930_01"}`。
`resolution` 只能是 `succeeded`、`failed`、`cancelled`；`evidenceRef` 是 1-64 位
ASCII 字母、数字、`_` 或 `-` 组成的非敏感证据标识，不是供应商原始响应、URL、token
或输入文本。应先在线下核实供应商状态。重复提交同一决议返回 200；冲突返回 409。

`SafeTask` 示例（时间戳为 Unix 毫秒，不是 ISO 字符串；真实 UUID 和时间由服务端生成）：

```json
{
  "taskId": "eeeeeeee-eeee-4eee-8eee-eeeeeeeeeeee",
  "state": "queued",
  "attempt": 0,
  "maxAttempts": 3,
  "target": { "deviceId": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa" },
  "steps": [
    {
      "stepId": "bbbbbbbb-bbbb-4bbb-8bbb-bbbbbbbbbbbb",
      "ordinal": 0,
      "kind": "health_check",
      "state": "pending",
      "attempt": 0,
      "target": { "deviceId": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa" }
    }
  ],
  "createdAt": 1790726400000,
  "updatedAt": 1790726400000
}
```

任务状态：`queued`、`dispatching`、`running`、`retry_waiting`、`cancel_requested`、
`needs_reconciliation`、`succeeded`、`failed`、`cancelled`、`timed_out`。
步骤状态：`pending`、`claimed`、`running`、`succeeded`、`failed`、`timed_out`、
`cancelled`、`skipped`。`steps[].ordinal` 从 0 开始。不要从进度或 `attempt` 推断
物理设备执行是否成功；列表与详情不会返回步骤参数、供应商回执、结果、错误详情、日志或截图
URL。当前 PostgreSQL 读取步骤时的 `attempt` 也是 0 占位，不能用于精确展示步骤重试次数。

## 错误与产品边界

错误响应是 `{ "error": "<code>" }`。主要映射：

| HTTP | `error` | 说明 |
| --- | --- | --- |
| 400 | `idempotency_key_required` | 提交缺少请求头 |
| 400 | `invalid_task_request` | JSON、参数、目标或命令类型无效，包含 `input_text` |
| 400 | `invalid_page` | 列表页码或大小不合法 |
| 400 | `invalid_reconciliation` | 人工复核参数不合法 |
| 401 | `authentication_required` | 未登录或会话过期 |
| 403 | `permission_denied` | 缺少对应操作权限、精确任务页权限或管理员身份 |
| 404 | `not_found` | 分组不可见、任务不存在、任务不属于该组，或提交时设备不存在 |
| 409 | `execution_task_idempotency_conflict` | 同组重复键对应不同任务内容 |
| 409 | `reconciliation_conflict` | 人工决议与已保存状态冲突 |

设备适配器生产默认未配置。**202 只代表任务持久化并入队，不代表设备已执行成功。**
前端应查询状态并在未配置、失败或待人工复核时如实呈现，不能用本地定时器伪造成功。
当前接口不提供任务删除、脚本/模板目录、批量设备任务、步骤日志、错误明细或截图下载。
现有本地任务页中的这些操作不能直接映射到本 API；需要产品和后端另行确定契约。

联调建议：登录并选取可见分组和真实设备 → 创建单步 `health_check` → 列表/详情
核对同一 `taskId` → 原键重试核对 200 → 改内容核对 409 → 创建新任务并请求取消
→ 验证刷新后的状态、权限 403、跨组 404。成功执行路径只在显式测试适配器环境中
验证；不要将内存适配器视为生产设备连接。
