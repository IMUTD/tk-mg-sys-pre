# 数据库设计（成员与权限）

现网库 `tk_mg`。当前落地并维护的是 **成员与权限**：登录、七种角色、页面可见/删除、成员增删改查。页面矩阵写在 `apps/api/src/lib/pages.ts`，库表由 Drizzle 迁移 `0000`～`0017` 建出。

本文只描述这套表。其它业务表若库里还在，不属于本模块，不要按本文去扩。

---

## 1. 模块在做什么

管理员在「成员与权限」里建人、改角色、停用或删除。每个可配置角色创建时写入默认页面权限，之后从「成员权限」按人微调最终权限。登录用邮箱；登录后顶栏和个人设置显示名字。

| 角色值 | 中文 |
|--------|------|
| `administrator` | 管理员（全部页面，含成员与权限、工作日志；最终权限不能下调） |
| `operations_director` | 运营部长 |
| `operator` | 运营员 |
| `sales_director` | 销售部长 |
| `salesperson` | 销售员 |
| `engineering_director` | 工程部长 |
| `engineer` | 工程师 |

硬规则：

- `/members`、`/work-logs` 只有管理员能看，不能下放。
- `/overview` 谁都可以看（默认），谁都不能开删除（含管理员）。
- `/studio/*` 资源中心默认全员可看，删除只有部长级和管理员。
- 普通成员默认不能删；部长默认可删本部门页和资源中心。
- 删除按钮和删除接口只认 `can_delete = true`，不能用「能看就能删」。

## 2. 实体关系

```text
access_group 1──N user_group N──1 app_user
                                      │
                                      ├── 1──N app_session
                                      ├── 1──N user_page_permission
                                      └── 1──N audit_event（actor_id）

app_role ──N role_page_permission     （管理员不入库）
```

两层授权：

1. **页面**：`user_page_permission`（最终）← 新建时从角色默认矩阵复制。代码默认矩阵在 `defaultPagesForRole`；`role_page_permission` 可覆盖角色默认，空表则回落代码。
2. **数据范围**：`user_group`。名单不再展示授权分组；新建成员未选手动分组时，会挂上当前全部 `access_group`，避免其它接口按组过滤时一张看不到。

保存某成员页面权限后，吊销该成员未过期会话，下次登录才生效。合并权限时仍强制第 1 节硬规则。

## 4. 表结构

迁移：`apps/api/src/db/migrations/`。本模块相关：`0000` 身份与会话，`0001` `app_role`，`0013` `enabled`，`0016` `role_page_permission`，`0017` `display_name` / `user_page_permission`，`0018` 移除旧版可逆登录密码密文字段。

### 4.1 `access_group` 数据范围分组

```sql
CREATE TABLE access_group (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name text NOT NULL UNIQUE,
  created_at timestamptz NOT NULL DEFAULT now()
);

COMMENT ON TABLE access_group IS '数据范围分组；成员名单不展示，新建成员默认同步全部组';
COMMENT ON COLUMN access_group.id IS '分组 UUID';
COMMENT ON COLUMN access_group.name IS '分组名，库内唯一';
COMMENT ON COLUMN access_group.created_at IS '创建时间';
```

### 4.2 `app_user` 成员

```sql
CREATE TABLE app_user (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  email text NOT NULL UNIQUE,
  display_name text NOT NULL DEFAULT '',
  password_hash text NOT NULL,
  role app_role NOT NULL,
  enabled boolean NOT NULL DEFAULT true,
  created_at timestamptz NOT NULL DEFAULT now()
);

COMMENT ON TABLE app_user IS '成员：登录账号、展示名、角色';
COMMENT ON COLUMN app_user.id IS '成员 UUID';
COMMENT ON COLUMN app_user.email IS '登录账号（邮箱），库内唯一，小写存储';
COMMENT ON COLUMN app_user.display_name IS '展示名：顶栏和个人设置使用；空则回落邮箱；新建时从动漫/影视/动物/明星名随机';
COMMENT ON COLUMN app_user.password_hash IS '登录密码哈希（Bun.password）';
COMMENT ON COLUMN app_user.role IS '角色枚举 app_role';
COMMENT ON COLUMN app_user.enabled IS 'false 则不能登录';
COMMENT ON COLUMN app_user.created_at IS '创建时间';
```

登录校验只使用 `password_hash`。创建成员和重置密码只接收一次明文用于哈希，之后 API、审计和前端名单都不保存或返回可逆登录密码。不能删除自己；不能删掉最后一个启用中的管理员；有业务引用时改为停用。

### 4.3 `user_group` 成员所属分组

```sql
CREATE TABLE user_group (
  user_id uuid NOT NULL REFERENCES app_user (id) ON DELETE CASCADE,
  group_id uuid NOT NULL REFERENCES access_group (id) ON DELETE CASCADE,
  PRIMARY KEY (user_id, group_id)
);

COMMENT ON TABLE user_group IS '成员与数据分组多对多';
COMMENT ON COLUMN user_group.user_id IS '成员';
COMMENT ON COLUMN user_group.group_id IS '分组';
```

### 4.4 `role_page_permission` 角色默认页面权限

管理员不写这张表。空表时 `loadMergedPageAccess` 用代码默认矩阵。

```sql
CREATE TABLE role_page_permission (
  role app_role NOT NULL,
  page_key text NOT NULL,
  can_view boolean NOT NULL,
  can_delete boolean NOT NULL,
  PRIMARY KEY (role, page_key)
);

COMMENT ON TABLE role_page_permission IS '角色默认可见/删除；管理员不入库';
COMMENT ON COLUMN role_page_permission.role IS '可配置角色，不含 administrator';
COMMENT ON COLUMN role_page_permission.page_key IS '前端路由，如 /operations/devices';
COMMENT ON COLUMN role_page_permission.can_view IS '能否看到并进入该页面';
COMMENT ON COLUMN role_page_permission.can_delete IS '该页删除按钮与删除接口；必须同时 can_view';
```

### 4.5 `user_page_permission` 成员最终页面权限

```sql
CREATE TABLE user_page_permission (
  user_id uuid NOT NULL REFERENCES app_user (id) ON DELETE CASCADE,
  page_key text NOT NULL,
  can_view boolean NOT NULL,
  can_delete boolean NOT NULL,
  PRIMARY KEY (user_id, page_key)
);

COMMENT ON TABLE user_page_permission IS '成员最终页面权限，新建时从角色默认复制，之后由管理员微调';
COMMENT ON COLUMN user_page_permission.user_id IS '成员';
COMMENT ON COLUMN user_page_permission.page_key IS '前端路由';
COMMENT ON COLUMN user_page_permission.can_view IS '能否看到并进入该页面';
COMMENT ON COLUMN user_page_permission.can_delete IS '该页删除按钮与删除接口';
```

无行时按角色默认补种。读写走 `jsonb_to_recordset`，payload 必须是 JSON 数组。

### 4.6 `app_session` 登录会话

```sql
CREATE TABLE app_session (
  id uuid PRIMARY KEY,
  user_id uuid NOT NULL REFERENCES app_user (id) ON DELETE CASCADE,
  token_hash text NOT NULL UNIQUE,
  expires_at timestamptz NOT NULL,
  revoked_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now()
);

COMMENT ON TABLE app_session IS '登录会话；Cookie tk_mg_session 对应 token 的 SHA-256';
COMMENT ON COLUMN app_session.id IS '会话 UUID';
COMMENT ON COLUMN app_session.user_id IS '成员';
COMMENT ON COLUMN app_session.token_hash IS '会话 token 的 SHA-256，唯一';
COMMENT ON COLUMN app_session.expires_at IS '过期时间，默认 8 小时';
COMMENT ON COLUMN app_session.revoked_at IS '撤销时间；改权限或退出登录时写入';
COMMENT ON COLUMN app_session.created_at IS '创建时间';
```

`GET /api/auth/session` 返回 `email`、`displayName`、`role`、`pages`。`displayName` 来自 `display_name`，空则回落邮箱。

### 4.7 `audit_event` 工作日志

```sql
CREATE TABLE audit_event (
  id uuid PRIMARY KEY,
  actor_id uuid NOT NULL REFERENCES app_user (id) ON DELETE RESTRICT,
  action text NOT NULL,
  outcome text NOT NULL,
  target text NOT NULL,
  metadata jsonb NOT NULL DEFAULT '{}'::jsonb,
  created_at timestamptz NOT NULL DEFAULT now()
);

COMMENT ON TABLE audit_event IS '不可变审计；工作日志页仅管理员可查';
COMMENT ON COLUMN audit_event.id IS '事件 UUID';
COMMENT ON COLUMN audit_event.actor_id IS '操作者';
COMMENT ON COLUMN audit_event.action IS '动作名，如 member.create';
COMMENT ON COLUMN audit_event.outcome IS '结果：allowed / denied / 业务码';
COMMENT ON COLUMN audit_event.target IS '对象标识';
COMMENT ON COLUMN audit_event.metadata IS '附加 JSON，不含解密后的密码';
COMMENT ON COLUMN audit_event.created_at IS '发生时间';
```

## 5. 默认权限矩阵

实现以 `apps/api/src/lib/pages.ts` 与 `apps/web/src/lib/pages.ts` 为准，两端必须一致。

| 页面 | 运营员 | 运营部长 | 销售员 | 销售部长 | 工程师 | 工程部长 | 管理员 |
|------|--------|----------|--------|----------|--------|----------|--------|
| 运营概览 | 看 | 看 | 看 | 看 | 看 | 看 | 看（不能删） |
| 运营中心核心 | 看 | 看+删 | — | — | — | — | 看+删 |
| 配置中心 | — | 看+删 | — | — | — | — | 看+删 |
| 营销 / 积分商场 | — | 仅运营业绩 | 看 | 看+删 | — | — | 看+删 |
| 工程中心 | — | — | — | — | 看 | 看+删 | 看+删 |
| 资源中心 | 看 | 看+删 | 看 | 看+删 | 看 | 看+删 | 看+删 |
| 工作日志 | — | — | — | — | — | — | 看 |
| 成员与权限 | — | — | — | — | — | — | 看（不能下放） |

「看」= `can_view`。增改跟查看走一起。「看+删」= 另开 `can_delete`。

## 6. 使用说明

1. 空库先跑 Drizzle 迁移，再 `bootstrap-admin` 写入首位管理员（`ADMIN_BOOTSTRAP_EMAIL` / `ADMIN_BOOTSTRAP_PASSWORD`）。邮箱已存在则拒绝覆盖。
2. 管理员在 `/members` 新建成员：邮箱、密码、角色；名字可掷骰子。创建成功即写入 `user_page_permission`。
3. 「成员权限」列进入后才能改最终 `can_view` / `can_delete`。面板不展示工作日志和成员页；运营概览删除开关锁死。
4. 改角色会按新角色默认矩阵重置该人页面权限。
5. 登录页填邮箱；顶栏显示 `display_name`。
6. 不要把其它产品的菜单或权限表直接打进 `tk_mg`。
