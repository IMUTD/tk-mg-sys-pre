# 设备适配器厂商对接清单

本文是接入真实云手机厂商、内网盒子或模拟器协议前的技术对接清单。它不规定某一家供应商的实现方式，而是规定供应商能力如何映射到仓库已经稳定的 `DeviceAdapter` 契约、API 命令状态机和审计模型。

## 1. 接入边界

真实供应商实现必须位于 `packages/device-adapter`，业务 API 只依赖 `DeviceAdapter`。供应商 SDK、HTTP API、WebSocket、盒子内网协议和鉴权细节不得进入 `apps/api` 或 `apps/web`。

```text
Web
  -> API routes / service
  -> durable device_command + device_command_event + audit_event
  -> executor claim boundary
  -> DeviceAdapter
  -> vendor cloud / internal box / emulator
```

本阶段的 `InMemoryDeviceAdapter` 只是契约实现，不代表任何真实设备能力；生产默认使用 `createUnconfiguredDeviceAdapter`，不会伪造成功。真实适配器上线前，必须复用适配器包的共享契约测试，并补充供应商特有的集成测试。

## 2. 首次对接必须确认的协议问题

### 2.1 目标和身份

需要供应商书面确认以下标识的生命周期和唯一性：

| 仓库概念 | 需要确认 | 不能默认的假设 |
| --- | --- | --- |
| `deviceId` | 是主机、租户设备、盒子还是云资源 ID | 不能假设本地登记 ID 能直接调用供应商 |
| `instanceId` | 是实例 ID、槽位号、端口还是临时会话 ID | 不能只保存显示编号 |
| 设备/实例关系 | 实例是否会迁移、重建或复用 ID | 不能把 index 当永久身份 |
| 供应商回执 | 回执是否可长期查询、是否跨账号唯一 | 不能把回执当最终结果 |
| 凭证范围 | 凭证绑定租户、设备、实例还是命令 | 不能在业务层保存供应方 token |

必须明确供应商 ID 与本地设备/实例登记的绑定表或配置来源。绑定变化时，旧命令的审计和结果仍需可查询，不能因为设备重新绑定而改变历史命令含义。

### 2.2 能力矩阵

对每个命令填写以下矩阵，未确认的能力必须标记为“不支持”或“待确认”，不能用成功回执代替。

| 命令 | 设备级 | 实例级 | 异步 | 可查询 | 可取消 | 幂等 | 超时单位 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `health_check` | 必须明确 | 可选 |  |  |  |  |  |
| `capture_screen` |  | 推荐 |  |  |  |  |  |
| `launch_app` |  | 必须 |  |  |  |  |  |
| `stop_app` |  | 必须 |  |  |  |  |  |
| `tap` |  | 必须 |  |  |  |  |  |
| `swipe` |  | 必须 |  |  |  |  |  |
| `input_text` |  | 必须 |  |  |  |  |  |

对不支持的命令返回稳定的 `unsupported` 错误码，不得把供应商原始错误字符串直接作为 API 错误码。

## 3. 命令参数与脱敏

供应商适配器接收的输入必须先通过仓库命令 schema。业务层不能透传 `unknown`、厂商 JSON 或任意扩展字段。

当前命令参数的最小语义如下：

| 命令 | 参数 | 对接注意事项 |
| --- | --- | --- |
| `health_check` | 无业务参数 | 明确探测的是连通、设备在线还是实例可用 |
| `capture_screen` | 目标实例 | 明确返回原图、压缩图、临时 URL 还是任务回执 |
| `launch_app` | `appId` | 确认使用包名、应用 ID 还是供应商应用记录 ID |
| `stop_app` | `appId` | 确认停止失败时是否视为已停止 |
| `tap` | `x`, `y` | 确认坐标原点、方向、旋转和分辨率换算 |
| `swipe` | 起止坐标、持续时间 | 确认最小/最大持续时间及设备旋转规则 |
| `input_text` | 文本 | 业务持久化只保存长度和指纹；供应商日志也必须脱敏 |

禁止持久化或写入普通日志：

- 账号密码、短信验证码、会话 token、供应商 token。
- `input_text` 原文及可逆编码。
- 截图二进制、未经授权的供应商图片 URL。
- 包含上述内容的供应商原始响应或异常堆栈。

供应商适配器应返回结构化、可序列化的错误：错误码、是否可重试、是否已被供应商接受，以及必要的非敏感诊断信息。诊断信息必须经过长度限制和字符过滤。

## 4. 回执、状态和状态映射

API 状态机是持久化事实，适配器只提供供应商结果。推荐映射：

| 供应商现象 | API 状态 | 适配器错误码 | 是否重试 |
| --- | --- | --- | --- |
| 已创建但尚未执行 | `queued` | 无 | 继续查询 |
| 供应商正在执行 | `running` | 无 | 继续查询 |
| 明确成功 | `succeeded` | 无 | 否 |
| 供应商拒绝参数/权限 | `failed` | `invalid_request` / `permission_denied` | 否 |
| 设备不可用或离线 | `failed` | `unavailable` | 按策略有限重试 |
| 请求超过适配器超时 | `timed_out` | `timeout` | 按命令策略决定 |
| 取消已被接受 | `cancelled` | 无 | 否 |
| 查询不到供应商任务 | 不得直接成功 | `not_found` | 先确认是否为延迟可见 |
| 供应商能力不存在 | `failed` | `unsupported` | 否 |

必须回答“提交超时但供应商可能已接受”这一情况：

1. 提交请求是否有供应商幂等键。
2. 是否能用本地命令 ID 或幂等键查询已接受的请求。
3. 查询不到时多久后才判定失败。
4. API 重试是否可能产生第二个真实操作。

如果供应商不能提供幂等提交或查询能力，必须在上线评审中明确接受重复操作风险，不能由 API 静默掩盖。

## 5. 幂等、重复提交和执行恢复

本地 API 使用 `(group_id, device_id, idempotency_key)` 做幂等约束。适配器实现必须同时确认：

- 相同幂等键和等价参数返回同一供应商回执或同一可查询任务。
- 相同幂等键但目标、命令类型或参数变化返回 `conflict`。
- 供应商幂等键长度、字符集和过期时间。
- 供应商是否区分“请求已接收”和“操作已完成”。
- API 进程在提交成功、持久化结果前崩溃时如何恢复。

命令仓储已经通过持久命令记录 claim，在事务外调用适配器，最后使用带 claim token 的条件更新写回结果；独立执行器尚未部署。适配器必须支持重复查询和安全重放；不能要求 API 在事务中保存供应商连接或 SDK 对象。

## 6. 取消语义

对每个命令确认以下时间窗口：

| 阶段 | 取消请求的期望行为 |
| --- | --- |
| API 尚未调用供应商 | 本地命令直接进入 `cancelled`，不得调用供应商 |
| 已 claim、尚未提交 | 调用供应商取消或阻止提交 |
| 已提交、执行中 | 调用供应商取消；等待最终取消或明确失败 |
| 已完成 | 取消幂等返回完成结果，不改变历史结果 |
| 供应商不支持取消 | API 返回明确不可取消错误，不能伪造 `cancelled` |

必须确认取消是强制终止、软取消、停止后续步骤，还是仅停止状态轮询。还要确认取消请求是否收费、是否产生部分结果，以及供应商是否会在取消后继续回调或完成任务。

## 7. 超时、重试和限流

对接前必须取得供应商的：

- 连接、提交、查询、取消各自超时建议。
- HTTP 状态码或协议错误到规范化错误码的映射。
- 限流维度：租户、设备、实例、IP 或 token。
- `Retry-After` 或等价退避信息。
- 最大并发、单设备串行约束和操作冷却时间。
- 供应商任务最长保留和查询窗口。

重试只允许发生在明确可重试的错误上，并且必须受次数、时间和命令类型策略限制。`tap`、`swipe`、`input_text` 等非幂等动作默认不能因为网络超时自动重试，除非供应商提供可靠幂等键和最终状态查询。

## 8. 健康检查语义

`health(target)` 与 `health_check` 命令必须分别说明：

- 连接器自身是否已配置。
- 供应商 API 是否可达。
- 设备是否在线。
- 目标实例是否可用。
- 账号余额、配额或租约是否阻止操作。
- 结果的观测时间和有效期。

不能把“供应商 API 返回 200”直接映射为设备在线。健康检查失败需要稳定错误码和非敏感原因；前端应能区分未配置、不可用、超时和业务拒绝。

## 9. 截图产物与访问策略

`capture_screen` 需要在接入前确定完整产物链路：

1. 供应商返回二进制、base64、临时 URL 还是永久对象 ID。
2. API 是否需要把产物复制到受控 storage-adapter。
3. 产物引用是否包含敏感 query token。
4. 谁能读取截图，是否按 group/device/command 做授权。
5. 产物过期、删除、重新获取和审计策略。
6. 图片格式、大小上限、压缩和病毒扫描要求。

推荐 API 只持久化受控的 `resultReference`，前端通过授权 API 获取短期访问地址。供应商 URL 不得原样写入审计、命令列表或浏览器 HTML。若供应商无法提供安全引用，先返回 `no_artifact` 或 `artifact_unavailable`，不要把二进制塞进命令结果 JSON。

## 10. 供应商安全与合规确认

上线前必须确认：

- token 是否支持最小权限、轮换和吊销。
- token 是否按 group/device 隔离。
- SDK 是否在错误、debug、HTTP trace 中打印凭证或命令文本。
- TLS、证书校验、代理和内网 DNS 要求。
- 供应商是否保留操作日志，日志保留多久，是否能删除敏感内容。
- 账号、设备画面和输入文本是否跨租户或跨地域存储。
- 供应商回调是否需要签名、重放保护和来源校验。
- 合约、数据保留和合规区域要求。

任何需要将供应商密钥放入浏览器或前端配置的方案都不得直接接受，必须回到 API/适配器边界重新设计。

## 11. 适配器实现交付物

真实适配器合并前至少应提供：

- 独立 workspace package 和清晰的 `DeviceAdapter` 实现。
- 供应商能力矩阵及不支持命令列表。
- 命令参数到供应商参数的映射说明。
- 错误码映射表和可重试矩阵。
- 供应商幂等、查询、取消和超时证明或集成测试。
- 共享契约测试全部通过。
- 供应商 sandbox/mock server 集成测试。
- input_text、token、截图 URL 的脱敏测试。
- 设备离线、重复提交、提交超时、查询延迟、取消竞态测试。
- 运行配置、密钥轮换、健康检查和故障排查文档。

适配器不得新增 Hono、Drizzle/PostgreSQL、React 或业务权限模块依赖。

## 12. 上线验收清单

### 协议

- [ ] 设备和实例身份的唯一性与生命周期已确认。
- [ ] 七类命令的能力矩阵已填写。
- [ ] 提交、查询、取消、回调协议已定稿。
- [ ] 幂等键、回执和最终结果语义已验证。

### 数据与安全

- [ ] API 只保存脱敏参数、错误码和受控结果引用。
- [ ] 账号密码、token、输入文本和截图二进制不会进入日志或审计。
- [ ] 截图访问策略、过期和删除策略已验证。
- [ ] 供应商 token 轮换和最小权限已验证。

### 可靠性

- [ ] 超时、限流、退避和最大重试已配置。
- [ ] 非幂等命令不会因未知提交结果自动重复执行。
- [ ] claim、租约、恢复和取消竞态已有测试。
- [ ] 供应商异常不会卡住本地命令状态机。

### 产品验收

- [ ] 健康检查能区分未配置、不可用、超时和成功。
- [ ] 截图无产物时明确展示无产物，不显示伪造画面。
- [ ] 跨分组访问返回 404，权限拒绝写审计。
- [ ] API、适配器契约、PostgreSQL 和 Playwright 验收全部通过。

## 13. 建议对接顺序

1. 先取得供应商 sandbox 和能力矩阵。
2. 先实现 health/listInstances，再实现查询型命令。
3. 先验证 `capture_screen` 的产物引用和权限，再接前端展示。
4. 再接启动/停止等应用命令。
5. 最后接 tap、swipe、input_text 等非幂等或敏感操作。
6. 在独立执行器上线前，完成 claim、恢复、取消和限流压测。

任何未回答的问题都应进入上线阻塞项，而不是在适配器中加入猜测性的兼容分支。
